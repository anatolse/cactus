## Why

The Cactus DSL has been developed bottom-up — lexer, parser, semantic analyzer, backends, stdlib. This has produced a coherent implementation, but without a stated language identity the design accumulates drift: systems that are half-declarative and half-scripting, spec language that over-promises runtime safety, and features evaluated on their own merits rather than against a unified standard.

A language philosophy document establishes the authoritative answer to questions like:
- "Should this feature be in author code or generated by the backend?"
- "Is this too much imperative power for a declarative DSL?"
- "Does this feature help authors describe mechanics, or does it make them write engine plumbing?"

Without this document, every feature discussion restarts from scratch. With it, the language has a stable identity that guides all future decisions.

## What Changes

- Create `openspec/specs/language-philosophy/spec.md` — the authoritative language identity and design principles document
- The document defines: language identity, the author/backend split, the declarative/restricted-imperative boundary, predictability requirements, and explicit non-goals
- No compiler code changes — this is a documentation and design governance change
- Existing specs are reviewed and flagged where they conflict with the philosophy

## Capabilities

### New Capabilities
- `language-philosophy`: The authoritative language identity, design principles, and author/backend boundary definitions

### Modified Capabilities
- None — this change creates a reference document; it does not change existing behavior. Subsequent changes that conflict with the philosophy will reference it in their proposals.

## Impact

- Creates `openspec/specs/language-philosophy/spec.md` (primary output)
- The `dsl_showcase.cactus` comments are updated to reference the philosophy
- Existing specs are reviewed against the philosophy and any conflicts are noted as future changes (not fixed in this change)
- All future change proposals SHOULD reference relevant philosophy principles in their "Why" section
